## Brief, pillars and loop

Solo developer, beginner in engine programming with multiple LLM-assisted games already built, 20+ hours/week; **3v3, Mac and Windows**, keyboard/mouse. **$0 asset budget**. First finish line: polished private Steam-hosted matches with friends.

- Responsive, deliberate close-quarters movement and readable combat.
- Stealth through sound: nearby enemies hear proximity speech; team radios can be stolen.
- Breaching changes routes and sightlines; reinforcement and stronger tools provide counterplay.
- Repeatable attack/defend bomb rounds with between-round equipment spending.
- Grounded industrial office at night: warm lamps/cool exterior; visibility takes priority.

Loop: buy/equip → prepare/infiltrate → listen/communicate → breach/fight → plant/defuse or eliminate → resolve/reward → next round and side swap.
References: [quiet approach](references/quiet-approach.png), [reinforced breach](references/reinforced-breach.png). Illustrations are targets, not proof of engine quality/performance.

Built (Session 05, pending acceptance) — host-authoritative match on the office graybox, `game/scripts/net/`:
- `net_cmd.gd` (`NetCmd`): one 60 Hz input (seq, round, view tick, quantised move, yaw/pitch, absolute button states incl. wanted tool; 22 bytes). `Player.simulate(cmd)` and `Loadout.apply_cmd(cmd)` are the only gameplay step — offline, host and client prediction all use them (offline smoke tests unchanged except one: plaster now penetrates).
- `net_match.gd` (`NetMatch`, child of the graybox when in a session; uses only Godot `multiplayer`, so ENet and SteamMultiplayerPeer behave the same). Host: per-player command buffer processed in seq order (duplicates/old seqs dropped, old-round commands consumed without effect, credit budget 1 command/tick + 1.7% drift, cap 8, ≤3/tick catch-up, so flooding can't speed a player up); dead players can only look; 20 Hz snapshots (53 B/player: pos/vel/yaw/pitch/height/flags/health/ack/ammo/charges/teleport counter). Client: predicts movement + ammo, reconciles on snapshots (replays unacked commands; ammo corrected by delta), interpolates others 100 ms behind. Reliable events with round id: JOINED/LEFT, CHARGE/DETONATE (charge id, owner), WALL (id, state, revision — stale/duplicate revisions ignored), HIT (shooter feedback), KILLED, ROUND (full state), REJECT, FACE. Joiners get a full snapshot (round, walls+revisions, live charges, players). Clients send commands with the last 4 repeated (loss tolerance) plus pings for RTT.
- Hits: host-only, `Ballistics` tests players analytically (capsule r 0.3) on every shot segment; **lag compensation** rewinds other players' hit volumes to the shooter's viewed tick, bounded to 12 ticks (200 ms). Rule: walls are always evaluated in their *current* host state — walls only open within a round and resets bump the round id, so a rewound shot can never pass a wall the shooter couldn't see through. Health 100, rifle 20 (×0.5 through an ordinary plaster panel, ×0.85 glass, max 2 surfaces, ≤0.3 m thick boxes; reinforced/metal, floors, crates stop rounds). Glass no longer blocks shots.
- Charges: placement checked by the host from its authoritative camera; simultaneous placement on one panel → exactly one charge, loser gets "Charge already placed here"; the host's charge breaches, clients' copies only count down and wait for the WALL/DETONATE events. Host T = new round: walls intact (rev 0), charges/marks/effects cleared, everyone respawned (3 corridor spawns team red, 3 room spawns team blue, alternating by join).
- Flow: hosting enters the match; clients enter after registration; host leaving → clients return to the menu showing "Host left the game"; client leaving → removed everywhere. Protocol bumped to 2 (`0.1.0-p2+commit`). Practice targets are offline-only. HUD: HP, round, RTT, KB/s, corrections, roster with HP/DOWN.
- Tests: `net_test.gd` (`NetTest`) bots play only through `NetCmd`s; the host orchestrates and compares every client's digest (round, walls state/revision + collision = authored parts, everyone's HP/alive, own ammo/charges, live charges, position ≤5 cm). Scenarios: simultaneous movement, LOS damage/ammo, strafing target with lag comp on/off, penetration ordinary vs reinforced, simultaneous charge race + breach + walking through the new opening, late join reproduces openings, death (can't move/shoot), forged replayed/old-round commands and stale/duplicate events, 3 resets with node counts, client disconnect, host departure.
