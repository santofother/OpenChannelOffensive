## 2. Quality benchmark (the two reference images)

Targets, not proof of engine quality; match their **design language and readability at game camera distances**, within a realistic real-time budget.

- [references/quiet-approach.png](../references/quiet-approach.png): matte black polymer carbine with a holographic sight in first person, suppressor, picatinny rail ticks, worn gloves and sleeves; operator with plate carrier, pouches, radio on the chest, helmet with headset, kneepads and holster. Low-key lighting, so silhouettes and material values must read in shadow.
- [references/reinforced-breach.png](../references/reinforced-breach.png): the breach charge as a chunky clamped device with a hazard-striped panel, glowing orange status light and a trailing wire; reinforced wall panels with riveted steel plates and red-painted frames; helmet/vest/glove detail; insulation, studs and paper in damaged plaster (map/FX work stays in 09, this session only supplies the gear).

Concrete bar for every model: believable silhouette from the first-person camera and from 5–15 m; hard-surface bevels catching light; at least three material zones (e.g. polymer, metal, glove/cloth) with roughness variation; small functional details (rails, screws, vents, straps, LEDs); consistent wear level; one shared scale and handedness. Final judgement is by side-by-side in-engine screenshots against the references, not by polygon count.

## 3. Asset pipeline (Blender MCP → Godot)

- **Source of truth:** one `.blend` per family under `art/blend/` (weapons, charges-and-kits, wearables, grenades, attachments). Modular pieces (receiver, rail, sight, magazine) so attachments and variants reuse parts. Commit the `.blend` files with the code; exports are regenerated, not hand-edited.
- **Workflow per asset:** (1) inspect scene (`get_objects_summary`) and units (metres, +Y up in Blender, export with Godot's −Z forward); (2) block out silhouette, bevel, add detail meshes, UV unwrap only what needs texture; (3) author materials with Principled BSDF using flat colours plus small baked/procedural masks (wear, edge dirt) — no external texture packs needed; (4) check with `get_screenshot_of_area_as_image` / `render_viewport_to_path` against the reference; (5) export glTF 2.0 binary (`.glb`) to `game/assets/models/<family>/` with origins at the grip/pivot, named parts for animated bits (magazine, slide, charge LED, clamp).
- **Budgets (proposed, to be measured):** first-person gun ≤ 25k tris, world/stand-in form ≤ 3k, grenade ≤ 3k, charge ≤ 12k, kit/medkit ≤ 6k, operator body ≤ 20k; materials ≤ 4 per item; 1k–2k textures only if a baked mask is needed. Record actual counts; reduce before lowering the resolution baseline.
- **Godot side:** import glTF, set materials to the project's palette conventions (z-clip scale / FOV override for viewmodels as in `viewmodel.gd`), keep collision primitive, name sockets (`Muzzle`, `Sight`, `Rail_Top`, `Rail_Side`, `Hand_L`, `Hand_R`) for attachments and hand placement. Keep code-generated placeholders as the fallback when a model is missing so tests and headless runs never depend on art.
- **Licensing:** self-made in Blender, so no third-party licence is required; if any reference geometry or free asset is used, record source URL, author, licence and modifications first (see asset-candidates). Do not trace or copy the reference illustrations' pixels as textures.

## 4. Functionality plan (host-authoritative)

All items follow the Session 08 patterns: catalog entry flips from `soon` to buyable; purchase atomic with request IDs; equipment resets each round unless a survivor-persistence rule says otherwise; effects driven by host events with round IDs; clients only render. Unit tests for rules, integration tests for replication.

| Item | Rule (proposal; tune in playtest) | Host / replication notes |
| --- | --- | --- |
| Frag grenade | Thrown on a fuse; radial damage falls off with distance; blocked by solid walls and reinforced panels, reduced through ordinary panels; does not breach walls | Projectile simulated on the host at 60 Hz with bounded bounces; clients get spawn + detonation events with the host tick |
| Flashbang | Blinds and mutes proportionally to distance and facing; line of sight required; wall-blocked | Blind amount computed per victim on the host, sent privately; a screen overlay and audio low-pass on that client only |
| Smoke | Volume that blocks sight for ~15 s; fades; does not block bullets or sound | Visual volume replicated by event; host does not need it for hits; cap simultaneous smokes |
| Incendiary | Fire zone denies an area for ~7 s, damage over time, does not pass walls | Host owns zone and damage ticks; clients render from event; cap zones |
| Weapon flashlight | Toggle (key chosen in session); lights a cone ahead; visible to others as a beam source so it reveals position | Replicate toggle bit in snapshots; light budget capped per match |
| Laser sight | Tighter hip spread; a visible dot/beam others can see | Replicate on/off; beam is cosmetic; spread change is host-checked |
| Night vision | Toggleable goggles: bright green view, bloom on lights, reduced in smoke; makes your own flashlight/laser conspicuous | Client-only post effect; host only tracks ownership and toggled bit; counters flashbang hard |
| Grenade slots | Per-role limits (e.g. total 3, ≤1 of each lethal) and keys; throw with LMB, cook/throw-distance proposal in session | Extends `Loadout.Tool` and NetCmd (3 tool bits are full at 8; widen the packed field and bump the protocol) |

Network, wall and economy interactions to test: grenades near breach openings and reinforced panels, smoke plus night vision, flash vs. dead/spectating players (no leaks to the dead), grenades thrown during prep (blocked), lag-compensation does not apply to throws, late joiner receives active smoke/fire zones, round reset clears every projectile and zone. All new effects obey the existing caps/budget rules and are measured on the six-player test.
